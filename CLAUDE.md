# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

**Conscious Claims** is a multi-agent orchestration system with three main components:

1. **TypeScript Agent System** (Root level): 5 specialized agents orchestrated by `agents-main.ts`, deployed to Buzz (decentralized agent platform)
2. **Python Claude-Hermes Bridge** (`claude-hermes-bridge.py`): HTTP server integrating Claude AI and Hermes orchestrator with shared context
3. **Full-Stack Application** (`/client`, `/server`): Frontend and backend for the main application (secondary focus for agent work)

### The Five Agents

| Agent | File | Channel | Purpose |
|-------|------|---------|---------|
| SEO Agent | `seo-agent.ts` | `#seo-reports` | Hourly audits of consciousclaims.com & energymarshalacademy.com for SEO/AEO |
| Blueprint Agent | `blueprint-agent.ts` | `#skool` | Builds GNPEC/WIOA-compliant training curriculum for Data Center Energy Control program |
| Warden Agent | `warden-agent.ts` | `#field-ops` | Field operations tracking: LOTO closeouts, energization events, audit readiness |
| Command Agent | `command-agent.ts` | `#command-center` | Business operations dashboard for Atlas AI services and data center training |
| Relay Agent | `relay-agent.ts` | `#relay-logs` | Coordinates data between agents via Zapier: Google Sheets, Smartsheet, SMS, Skool platform |

## Key Architecture Decisions

### ES Modules (ESM) with .js Extensions
- TypeScript configured with `"module": "ESNext"`
- All imports **must** include `.js` extensions: `import X from "./file.js"`
- CommonJS (`require`) patterns are incompatible; must use `import/export`
- Compile with `npm run build` to generate `dist/*.js` files

### Transport Layer: BuzzConnector
- Single abstraction for all agent communication to Buzz WebSocket
- Initialized in `agents-main.ts`, injected into each agent
- Constructor: `new BuzzConnector("Agent Name", "channel-name")`
- Methods: `connect()`, `postToChannel(message)`, `disconnect()`
- Auto-reconnects every 5 seconds on failure

### Orchestration Pattern
- `agents-main.ts` is the single entry point
- Initializes all 5 agents sequentially with their BuzzConnectors
- Each agent runs independently; coordination via Buzz channel messages
- Health checks every 60 seconds (see `agents-main.ts` line 65+)

### Environment Variables
- Loaded via `dotenv.config()` in `agents-main.ts` before agent initialization
- Required: `ANTHROPIC_API_KEY` (for Claude integration via bridge)
- Required: `BUZZ_URL` (default: `wss://conscious-command.communities.buzz.xyz`)
- Optional: `HERMES_URL` (default: `http://localhost:3001` for local orchestrator)
- Optional: `BRIDGE_PORT` (default: `9000` for Python HTTP server)
- Template: `.env.example`

## Deployment Options

### Option 1: TypeScript Agents Only (Fastest)
```bash
npm install && npm run build && npm start
```
Agents connect directly to Buzz. No Python required. No shared context with Claude.

### Option 2: With Claude Bridge
```bash
# Terminal 1: Start bridge
npm run bridge:install && npm run bridge

# Terminal 2: Start agents
npm start
```
Bridge runs on `localhost:9000`. Agents can call Claude via `/claude/request` endpoint. Shared contacts & messages logged.

### Option 3: Full Stack (Agents + Bridge + Hermes)
```bash
# Terminal 1: Hermes (if installed)
hermes serve

# Terminal 2: Claude Bridge
npm run bridge

# Terminal 3: TypeScript Agents
npm start
```
Full agent OS with orchestration, coordination, and Claude integration.

## Critical Details for Code Changes

### When Adding a New Agent
1. Create `new-agent.ts` in root directory
2. Follow pattern: extend from Agent base class or EventEmitter
3. In `agents-main.ts`, add:
   ```typescript
   import NewAgent from "./new-agent.js";
   const newAgent = new NewAgent();
   this.buzzConnectors.set("new", new BuzzConnector("New Agent", "new-channel"));
   await this.buzzConnectors.get("new")!.connect();
   ```
4. Build: `npm run build`
5. Import statement MUST have `.js` extension

### When Modifying BuzzConnector
- Changes affect ALL agents simultaneously
- Test with at least one agent before full deployment
- Ensure `connect()`, `postToChannel()`, `disconnect()` remain the signature

### When Updating Environment Variables
- Add to `.env.example` for documentation
- Ensure `.env` is in `.gitignore` (already configured)
- Load early in `agents-main.ts` via `dotenv.config()`

### TypeScript Compilation Issues
- Always run `npm run build` before `npm start`
- Module resolution: `"moduleResolution": "node"` in `tsconfig.json`
- Target: `"module": "ESNext"` requires `.js` extensions in imports
- If seeing "Cannot find module" errors, check:
  1. File exists
  2. Import has `.js` extension
  3. `npm run build` was run
  4. No stale files in `dist/` (safe to delete and rebuild)

## Bridge HTTP Endpoints (Python)

When running `npm run bridge`, these endpoints are available at `http://localhost:9000`:

```bash
# Health check
GET /health
→ {"status": "healthy", "agents": <count>}

# Contact management
POST /contacts/add
→ {"status": "added", "contact": {...}}

GET /contacts/list
→ [{name, email, company, phone, notes, added_by, timestamp}, ...]

# Message logging
POST /messages/send
→ {"status": "received", "timestamp": "..."}

GET /messages/list?channel=%23seo-reports
→ [{agent_name, channel, content, timestamp, context}, ...]

# Claude integration
POST /claude/request
Body: {"agent_name": "...", "prompt": "...", "context": {...}}
→ {"agent": "Claude", "response": "..."}
```

## Testing Strategy

1. **TypeScript Compilation**: `npm run build` (must succeed with no errors)
2. **Agent Orchestration**: `npm start` (check console for all 5 agents connecting to Buzz)
3. **Bridge Endpoints**: `curl http://localhost:9000/health` (if bridge running)
4. **Individual Agents**: `npm run test:blueprint` (for quick testing without full orchestration)

## Troubleshooting Quick Reference

| Issue | Check | Fix |
|-------|-------|-----|
| "Cannot find module" | ESM import has `.js` extension? | Add `.js`: `"./file.js"` |
| Compilation fails | TypeScript errors? | `npm run build` with full output |
| Agents won't connect | BUZZ_URL in .env correct? | Verify `wss://consious-command.communities.buzz.xyz` |
| Bridge not responding | Python 3.8+? Deps installed? | `npm run bridge:install` |
| Port 9000 in use | Another process running? | `lsof -i :9000` and kill if needed |
| stale dist/ files | Build artifacts outdated? | `rm -rf dist/ && npm run build` |

## When to Modify vs. Add

| Scenario | Action |
|----------|--------|
| Add new agent | Create new `.ts` file, register in `agents-main.ts` |
| Change how agents talk to Buzz | Modify `buzz-connector.ts` |
| Add new Buzz channel for existing agent | Update BuzzConnector initialization in `agents-main.ts` |
| Share data between agents | Use Relay Agent Zapier workflows or POST to bridge endpoints |
| Change agent-to-Claude communication | Modify `claude-hermes-bridge.py` or `/claude/request` endpoint |
| Add new Python dependency | Add to `requirements.txt`, run `npm run bridge:install` |

## Important Notes for Future Development

1. **No Direct Hermes Dependency**: Agents work without Hermes. Bridge is optional. Hermes is for orchestration only.
2. **Stateless Agents**: Each agent is independent. State is shared via Buzz channels or bridge HTTP endpoints.
3. **Real-Time First**: Agents post immediately to Buzz. Polling/scheduling is handled by Relay Agent via Zapier.
4. **Error Resilience**: Agents auto-reconnect to Buzz every 5 seconds. Bridge continues serving even if agents are offline.
5. **No Database Lock-In**: SharedContext in bridge uses in-memory storage (can be swapped for persistent DB).
6. **Always Use npm Scripts**: Never run `tsc` or `tsx` directly; use `npm run build`, `npm start`, `npm run bridge`.
